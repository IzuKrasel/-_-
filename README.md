sqlite3— Интерфейс DB-API 2.0 для баз данных SQLite 
Исходный код: Lib/sqlite3/

SQLite — это библиотека на языке C, предоставляющая легковесную дисковую базу данных, не требующую отдельного серверного процесса и позволяющую получать доступ к базе данных с помощью нестандартного варианта языка запросов SQL. Некоторые приложения могут использовать SQLite для внутреннего хранения данных. Также возможно создать прототип приложения с использованием SQLite, а затем перенести код на более крупную базу данных, такую ​​как PostgreSQL или Oracle.

Модуль sqlite3был написан Герхардом Херингом. Он предоставляет SQL-интерфейс, соответствующий спецификации DB-API 2.0, описанной в [ссылка на документацию].Соответствует требованиям PEP 249 и требует использования сторонней библиотеки SQLite .

Это необязательный модуль . Если он отсутствует в вашей копии CPython, обратитесь за документацией к вашему дистрибьютору (то есть к тому, кто предоставил вам Python). Если вы являетесь дистрибьютором, см. раздел « Требования к необязательным модулям» .

Учебное пособие 
В этом уроке вы создадите базу данных фильмов Монти Пайтона, используя базовые sqlite3функции. Предполагается базовое понимание концепций баз данных, включая курсоры и транзакции .

Во-первых, нам нужно создать новую базу данных и открыть соединение с ней, чтобы иметь возможность sqlite3с ней работать. Вызовите функцию sqlite3.connect()для создания соединения с базой данных tutorial.dbв текущем рабочем каталоге, неявно создав его, если оно не существует:

import sqlite3
con = sqlite3.connect("tutorial.db")
Возвращаемый Connectionобъект con представляет собой соединение с базой данных на диске.

Для выполнения SQL-запросов и получения результатов нам потребуется использовать курсор базы данных. Вызовите метод con.cursor()для его создания Cursor:

cur = con.cursor()
Теперь, когда у нас есть подключение к базе данных и курсор, мы можем создать таблицу базы данных movieсо столбцами для названия, года выпуска и оценки. Для простоты мы можем просто использовать имена столбцов в объявлении таблицы — благодаря гибкой типизации SQLite указание типов данных необязательно. Выполните запрос , вызвав :CREATE TABLEcur.execute(...)

cur.execute("CREATE TABLE movie(title, year, score)")
Мы можем убедиться в создании новой таблицы, выполнив запрос к sqlite_masterвстроенной в SQLite таблице, которая теперь должна содержать запись с movieопределением таблицы ( подробнее см. в разделе «Таблица схемыcur.execute(...) »). Выполните этот запрос, вызвав метод , присвойте результат методу resи вызовите метод res.fetchone()для получения результирующей строки:

res = cur.execute("SELECT name FROM sqlite_master")
res.fetchone()

Мы видим, что таблица создана, поскольку запрос возвращает объект, tupleсодержащий имя таблицы. Если мы запросим sqlite_masterнесуществующую таблицу spam, res.fetchone()то получим None:

res = cur.execute("SELECT name FROM sqlite_master WHERE name='spam'")

Теперь добавьте две строки данных, предоставленных в виде SQL-литералов, выполнив INSERTоператор, снова вызвав cur.execute(...):

cur.execute("""
    INSERT INTO movie VALUES
        ('Monty Python and the Holy Grail', 1975, 8.2),
        ('And Now for Something Completely Different', 1971, 7.5)
""")
Данное INSERTвыражение неявно открывает транзакцию, которую необходимо подтвердить перед сохранением изменений в базе данных ( подробнее см. в разделе «Управление транзакциямиcon.commit() »). Для подтверждения транзакции вызовите метод объекта соединения:

con.commit()
Мы можем убедиться в правильности вставки данных, выполнив SELECTзапрос. Используйте уже знакомый нам способ cur.execute(...), чтобы присвоить результат переменной res, и вызовите функцию res.fetchall()для возврата всех результирующих строк:

res = cur.execute("SELECT score FROM movie")
res.fetchall()
[(8.2,), (7.5,)]
В результате получается listдва объекта, по одному на каждую строку, каждый из которых содержит значение tupleэтой строки .score

Теперь вставьте еще три строки, вызвав cur.executemany(...):

data = [
    ("Monty Python Live at the Hollywood Bowl", 1982, 7.9),
    ("Monty Python's The Meaning of Life", 1983, 7.5),
    ("Monty Python's Life of Brian", 1979, 8.0),
]
cur.executemany("INSERT INTO movie VALUES(?, ?, ?)", data)
con.commit()  # Remember to commit the transaction after executing INSERT.
Обратите внимание, что ?для привязки к запросу используются заполнители data. Всегда используйте заполнители вместо форматирования строк для привязки значений Python к операторам SQL, чтобы избежать атак SQL-инъекций ( подробнее см. раздел «Как использовать заполнители для привязки значений в SQL-запросах »).

Мы можем убедиться в том, что новые строки были вставлены, выполнив SELECTзапрос, на этот раз перебрав результаты запроса:

for row in cur.execute("SELECT year, title FROM movie ORDER BY year"):
    print(row)

Наконец, убедитесь, что база данных записана на диск, вызвав функцию con.close() закрытия существующего соединения, открыв новое, создав новый курсор, а затем выполнив запрос к базе данных:

con.close()
new_con = sqlite3.connect("tutorial.db")
new_cur = new_con.cursor()
res = new_cur.execute("SELECT title, year FROM movie ORDER BY score DESC")
title, year = res.fetchone()
print(f'The highest scoring Monty Python movie is {title!r}, released in {year}')

sqlite3.complete_statement ( statement ) ​
Возвращает значение, Trueесли строковое выражение содержит одно или несколько полных SQL-выражений. Никакой синтаксической проверки или анализа не выполняется, за исключением проверки отсутствия незакрытых строковых литералов и завершения выражения точкой с запятой.

Например:

sqlite3.complete_statement("SELECT foo FROM bar;")
True
sqlite3.complete_statement("SELECT foo")
False
Эта функция может быть полезна при вводе данных из командной строки для определения того, является ли введенный текст полным SQL-запросом, или же требуется дополнительный ввод перед вызовом функции execute().

Примеры практического применения см. runsource()в файле Lib/sqlite3/__main__.py .

sqlite3.PARSE_COLNAMES​
Передайте значение этого флага параметру detect_typesconnect() , чтобы найти функцию конвертера, используя имя типа, полученное из имени столбца запроса, в качестве ключа словаря конвертера. Имя столбца запроса должно быть заключено в двойные кавычки ( "), а имя типа — в квадратные скобки ( []).

sqlite3. threadsafety
Целочисленная константа, требуемая DB-API 2.0, указывающая уровень потокобезопасности, sqlite3поддерживаемый модулем. Этот атрибут устанавливается на основе режима многопоточности по умолчанию , с которым скомпилирована базовая библиотека SQLite. Режимы многопоточности SQLite:

Однопоточный режим : В этом режиме все мьютексы отключены, и использование SQLite более чем в одном потоке одновременно небезопасно.

Многопоточный режим : В этом режиме SQLite может безопасно использоваться несколькими потоками при условии, что ни одно соединение с базой данных не используется одновременно в двух или более потоках.

Сериализованный режим : В сериализованном режиме SQLite можно безопасно использовать в нескольких потоках без каких-либо ограничений.

# Example taken from https://www.sqlite.org/windowfunctions.html#udfwinfunc
class WindowSumInt:
    def __init__(self):
        self.count = 0

    def step(self, value):
        """Add a row to the current window."""
        self.count += value

    def value(self):
        """Return the current value of the aggregate."""
        return self.count

    def inverse(self, value):
        """Remove a row from the current window."""
        self.count -= value

    def finalize(self):
        """Return the final value of the aggregate.

        Any clean-up actions should be placed here.
        """
        return self.count

values = [

    ("e", 1),
]
cur.executemany("INSERT INTO test VALUES(?, ?)", values)
con.create_window_function("sumint", 1, WindowSumInt)
cur.execute("""
    SELECT x, sumint(y) OVER (
        ORDER BY x ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS sum_y
    FROM test ORDER BY x
""")

    if string1 == string2:
        return 0
    elif string1 < string2:
        return 1
    else:
        return -1

con = sqlite3.connect(":memory:")
con.create_collation("reverse", collate_reverse)

cur = con.execute("CREATE TABLE test(x)")
cur.executemany("INSERT INTO test(x) VALUES(?)", [("a",), ("b",)])

set_authorizer ( authorizer_callback , / ) 
Зарегистрируйте вызываемый объект authorizer_callback, который будет вызываться при каждой попытке доступа к столбцу таблицы в базе данных. Пятый аргумент — это имя самого внутреннего триггера или представления, ответственного за попытку доступа, или Noneесли эта попытка доступа осуществляется непосредственно из входного SQL-кода.

Пожалуйста, ознакомьтесь с документацией SQLite относительно возможных значений первого аргумента и значения второго и третьего аргументов в зависимости от первого. Все необходимые константы доступны в модуле sqlite3.

резервное копирование ( цель , * , страницы = -1 , прогресс = None , имя = 'главный' , сон = 0.250 ) 
Создайте резервную копию базы данных SQLite.

    src.backup(dst, pages=1, progress=progress)

src.close()

Экземпляр Blobпредставляет собой файлоподобный объект , который может читать и записывать данные в BLOB-объект SQLite . Вызовите метод len(blob)для получения размера (количества байтов) BLOB-объекта. Используйте индексы и срезы для прямого доступа к данным BLOB-объекта.

con = sqlite3.connect(":memory:")

    blob.write(b"hello, ")
    blob.write(b"world.")
    # Modify the first and last bytes of our blob
    blob[0] = ord("H")
    blob[-1] = ord("!")

# Read the contents of our blob
with con.blobopen("test", "blob_col", 1) as blob:
    greeting = blob.read()

print(greeting)  # outputs "b'Hello, world!'"
con.close()

Возникло исключение из-за некорректного использования низкоуровневого C API SQLite. Другими словами, если возникает это исключение, это, вероятно, указывает на ошибку в модуле sqlite3. InterfaceErrorявляется подклассом Error.

исключение sqlite3. Ошибка базы данных
Исключение, генерируемое для ошибок, связанных с базой данных. Оно служит базовым исключением для нескольких типов ошибок базы данных. Оно генерируется неявно только через специализированные подклассы. DatabaseErrorявляется подклассом Error.

исключение sqlite3.DataError​
Исключение генерируется для ошибок, вызванных проблемами с обрабатываемыми данными, такими как числовые значения, выходящие за пределы допустимого диапазона, и слишком длинные строки. DataErrorявляется подклассом DatabaseError.

исключение sqlite3. OperationalError
Исключение генерируется для ошибок, связанных с работой базы данных и не обязательно находящихся под контролем программиста. Например, путь к базе данных не найден или транзакция не может быть обработана. OperationalErrorявляется подклассом DatabaseError.

исключение sqlite3. IntegrityError
Исключение возникает, когда нарушается целостность реляционной базы данных, например, если проверка внешнего ключа завершается неудачей. Это подкласс класса DatabaseError.

исключение sqlite3. InternalError
Исключение возникает, когда SQLite обнаруживает внутреннюю ошибку. Если оно возникает, это может указывать на проблему с библиотекой SQLite во время выполнения. InternalErrorявляется подклассом DatabaseError.

исключение sqlite3. ProgrammingError
Исключение генерируется в случае sqlite3ошибок программирования API, например, при указании неверного количества привязок к запросу или при попытке работы с закрытым объектом Connection. ProgrammingErrorЯвляется подклассом DatabaseError.

исключение sqlite3.NotSupportedError ¶
Исключение возникает в случае, если метод или API базы данных не поддерживаются базовой библиотекой SQLite. Например, установка параметра deterministic в Trueзначение create_function(), если базовая библиотека SQLite не поддерживает детерминированные функции. NotSupportedErrorявляется подклассом DatabaseError.

Как использовать заполнители для привязки значений в SQL-запросах 
В SQL-запросах обычно используются значения из переменных Python. Однако следует остерегаться использования строковых операций Python для составления запросов, поскольку они уязвимы для SQL-инъекций . Например, злоумышленник может просто закрыть одинарную кавычку и выполнить инъекцию для выбора всех строк:OR TRUE

# Never do this -- insecure!
symbol = input()
' OR TRUE; --
sql = "SELECT * FROM stocks WHERE symbol = '%s'" % symbol
print(sql)
SELECT * FROM stocks WHERE symbol = '' OR TRUE; --'
cur.execute(sql)
Вместо этого используйте подстановку параметров API базы данных. Чтобы вставить переменную в строку запроса, используйте заполнитель в строке и подставьте фактические значения в запрос, указав их в качестве tupleнабора значений во втором аргументе метода курсора execute().

В SQL-запросе могут использоваться два типа заполнителей: вопросительные знаки (стиль qmark) или именованные заполнители (стиль named). В стиле qmark параметры должны представлять собой последовательность , длина которой должна соответствовать количеству заполнителей, иначе ProgrammingErrorбудет сгенерировано исключение. В стиле named параметры должны быть экземпляром класса dict(или его подкласса), который должен содержать ключи для всех именованных параметров; любые дополнительные элементы игнорируются. Вот пример обоих стилей:

con = sqlite3.connect(":memory:")
cur = con.execute("CREATE TABLE lang(name, first_appeared)")

# This is the named style used with executemany():
data = (
    {"name": "C", "year": 1972},
    {"name": "Fortran", "year": 1957},
    {"name": "Python", "year": 1991},
    {"name": "Go", "year": 2009},
)
cur.executemany("INSERT INTO lang VALUES(:name, :year)", data)

# This is the qmark style used in a SELECT query:
params = (1972,)
cur.execute("SELECT * FROM lang WHERE first_appeared = ?", params)
print(cur.fetchall())
con.close()
Примечание Использование числовых заполнителей, предусмотренных PEP 249, не поддерживается. В случае их использования они будут интерпретироваться как именованные заполнители.
Как адаптировать пользовательские типы данных Python к значениям SQLite 
SQLite изначально поддерживает лишь ограниченный набор типов данных. Для хранения пользовательских типов данных Python в базах данных SQLite необходимо адаптировать их к одному из типов Python, которые SQLite понимает изначально .

Существует два способа адаптации объектов Python к типам SQLite: позволить объекту адаптироваться самостоятельно или использовать вызываемую функцию-адаптер . Последний вариант будет иметь приоритет над первым. Для библиотеки, экспортирующей пользовательский тип, может быть целесообразнее разрешить этому типу адаптироваться самостоятельно. Для разработчика приложения может быть более целесообразно взять управление на себя, зарегистрировав пользовательские функции-адаптеры.

Как писать адаптивные объекты 
Предположим, у нас есть Pointкласс, представляющий пару координат xи yв декартовой системе координат. Пара координат будет храниться в базе данных в виде текстовой строки, разделяемой точкой с запятой. Это можно реализовать, добавив метод, возвращающий соответствующее значение. Объект, передаваемый в протокол, будет иметь тип .__conform__(self, protocol)PrepareProtocol

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __conform__(self, protocol):
        if protocol is sqlite3.PrepareProtocol:
            return f"{self.x};{self.y}"

con = sqlite3.connect(":memory:")
cur = con.cursor()

cur.execute("SELECT ?", (Point(4.0, -3.2),))
print(cur.fetchone()[0])
con.close()
Как зарегистрировать вызываемые функции адаптера 
Другой вариант — создать функцию, которая преобразует объект Python в тип, совместимый с SQLite. Затем эту функцию можно зарегистрировать с помощью метода ` register_adapter().`.

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

def adapt_point(point):
    return f"{point.x};{point.y}"

sqlite3.register_adapter(Point, adapt_point)

con = sqlite3.connect(":memory:")
cur = con.cursor()

cur.execute("SELECT ?", (Point(1.0, 2.5),))
print(cur.fetchone()[0])
con.close()
Как преобразовать значения SQLite в пользовательские типы данных Python 
Создание адаптера позволяет преобразовывать пользовательские типы данных Python в значения SQLite. Для преобразования значений SQLite в пользовательские типы данных Python мы используем конвертеры .

Вернемся к Pointуроку. Мы сохранили координаты x и y, разделенные точками с запятой, в виде строк в SQLite.

Сначала определим функцию-конвертер, которая принимает строку в качестве параметра и создает Pointиз нее объект.

Примечание В функции конвертера всегда передается bytesобъект, независимо от базового типа данных SQLite.
def convert_point(s):
    x, y = map(float, s.split(b";"))
    return Point(x, y)
Теперь нам нужно указать, sqlite3когда следует преобразовывать заданное значение SQLite. Это делается при подключении к базе данных с помощью параметра detect_typesconnect() . Доступны три варианта:

Неявно: установить detect_types вPARSE_DECLTYPES

Явно: установить detect_types вPARSE_COLNAMES

В обоих случаях: установите detect_types в значение . Имена столбцов имеют приоритет над объявленными типами.sqlite3.PARSE_DECLTYPES | sqlite3.PARSE_COLNAMES

Следующий пример иллюстрирует неявный и явный подходы:

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

def adapt_point(point):
    return f"{point.x};{point.y}"

def convert_point(s):
    x, y = list(map(float, s.split(b";")))
    return Point(x, y)

# Register the adapter and converter
sqlite3.register_adapter(Point, adapt_point)
sqlite3.register_converter("point", convert_point)

# 1) Parse using declared types
p = Point(4.0, -3.2)
con = sqlite3.connect(":memory:", detect_types=sqlite3.PARSE_DECLTYPES)
cur = con.execute("CREATE TABLE test(p point)")

cur.execute("INSERT INTO test(p) VALUES(?)", (p,))
cur.execute("SELECT p FROM test")
print("with declared types:", cur.fetchone()[0])
cur.close()
con.close()

# 2) Parse using column names
con = sqlite3.connect(":memory:", detect_types=sqlite3.PARSE_COLNAMES)
cur = con.execute("CREATE TABLE test(p)")

cur.execute("INSERT INTO test(p) VALUES(?)", (p,))
cur.execute('SELECT p AS "p [point]" FROM test')
print("with column names:", cur.fetchone()[0])
cur.close()
con.close()
Рецепты адаптеров и преобразователей 
В этом разделе представлены рецепты для распространенных адаптеров и преобразователей.

import datetime as dt
import sqlite3

def adapt_date_iso(val):
    """Adapt datetime.date to ISO 8601 date."""
    return val.isoformat()

def adapt_datetime_iso(val):
    """Adapt datetime.datetime to timezone-naive ISO 8601 date."""
    return val.replace(tzinfo=None).isoformat()

def adapt_datetime_epoch(val):
    """Adapt datetime.datetime to Unix timestamp."""
    return int(val.timestamp())

sqlite3.register_adapter(dt.date, adapt_date_iso)
sqlite3.register_adapter(dt.datetime, adapt_datetime_iso)
sqlite3.register_adapter(dt.datetime, adapt_datetime_epoch)

def convert_date(val):
    """Convert ISO 8601 date to datetime.date object."""
    return dt.date.fromisoformat(val.decode())

def convert_datetime(val):
    """Convert ISO 8601 datetime to datetime.datetime object."""
    return dt.datetime.fromisoformat(val.decode())

def convert_timestamp(val):
    """Convert Unix epoch timestamp to datetime.datetime object."""
    return dt.datetime.fromtimestamp(int(val))

sqlite3.register_converter("date", convert_date)
sqlite3.register_converter("datetime", convert_datetime)
sqlite3.register_converter("timestamp", convert_timestamp)

Как использовать менеджер контекста подключения 
Объект Connectionможет использоваться в качестве менеджера контекста, который автоматически фиксирует или откатывает открытые транзакции при выходе из тела оператора контекста. Если тело оператора withзавершается без исключений, транзакция фиксируется. Если фиксация не удается или если тело оператора withвызывает необработанное исключение, транзакция откатывается. Если autocommitзначение равно False, после фиксации или отката неявно открывается новая транзакция.

Если при выходе из тела оператора нет открытой транзакции withили если autocommitзначение равно нулю True, менеджер контекста ничего не делает.

Примечание Менеджер контекста не открывает новую транзакцию и не закрывает соединение. Если вам нужен менеджер контекста для закрытия соединения, рассмотрите возможность использования contextlib.closing().
con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE lang(id INTEGER PRIMARY KEY, name VARCHAR UNIQUE)")

# Successful, con.commit() is called automatically afterwards
with con:
    con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))

# con.rollback() is called after the with block finishes with an exception,
# the exception is still raised and must be caught
try:
    with con:
        con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))
except sqlite3.IntegrityError:
    print("couldn't add Python twice")

# Connection object used as context manager only commits or rollbacks transactions,
# so the connection object should be closed manually
con.close()

Как создавать и использовать построчные фабрики 
По умолчанию sqlite3каждая строка представляется в виде tuple. Если tupleвам это не подходит, вы можете использовать sqlite3.Rowкласс или пользовательский row_factory.

Хотя row_factoryэтот параметр существует как в , так Cursorи в Connection, рекомендуется установить Connection.row_factory, чтобы все курсоры, созданные из соединения, использовали одну и ту же фабрику строк.

RowПредоставляет индексированный и регистронезависимый именованный доступ к столбцам с минимальными затратами памяти и влиянием на производительность tuple. Чтобы использовать Rowего в качестве фабрики строк, назначьте его атрибуту row_factory:

con = sqlite3.connect(":memory:")
con.row_factory = sqlite3.Row
Теперь запросы возвращают Rowобъекты:

res = con.execute("SELECT 'Earth' AS name, 6378 AS radius")
row = res.fetchone()
row.keys()
['name', 'radius']
row[0]         # Access by index.
'Earth'
row["name"]    # Access by name.
'Earth'
row["RADIUS"]  # Column names are case-insensitive.
6378
con.close()
Примечание FROMВ операторе можно опустить этот пункт SELECT, как в приведенном выше примере. В таких случаях SQLite возвращает одну строку со столбцами, определенными выражениями, например, литералами, с заданными псевдонимами .expr AS alias
Вы можете создать пользовательский объект row_factory , который будет возвращать каждую строку в виде массива данных dict, где имена столбцов будут сопоставлены со значениями:

def dict_factory(cursor, row):
    fields = [column[0] for column in cursor.description]
    return {key: value for key, value in zip(fields, row)}
Благодаря этому, запросы теперь возвращают dictвместо tuple:

con = sqlite3.connect(":memory:")
con.row_factory = dict_factory
for row in con.execute("SELECT 1 AS a, 2 AS b"):
    print(row)
{'a': 1, 'b': 2}
con.close()
Следующая фабрика строк возвращает именованный кортеж :

from collections import namedtuple

def namedtuple_factory(cursor, row):
    fields = [column[0] for column in cursor.description]
    cls = namedtuple("Row", fields)
    return cls._make(row)
namedtuple_factory()может использоваться следующим образом:

con = sqlite3.connect(":memory:")
con.row_factory = namedtuple_factory
cur = con.execute("SELECT 1 AS a, 2 AS b")
row = cur.fetchone()
row

row[0]  # Indexed access.
1
row.b   # Attribute access.
2
con.close()

Как обрабатывать текстовые кодировки, отличные от UTF-8 
По умолчанию sqlite3используется strадаптация значений SQLite в соответствии с типом данных. Это хорошо работает для текста, закодированного в UTF-8, но может не работать для других кодировок и недопустимых UTF-8. Для обработки таких случаев TEXTможно использовать пользовательский механизм .text_factory

Благодаря гибкой типизации SQLite , нередко встречаются столбцы таблиц с TEXTтипом данных, содержащим кодировки, отличные от UTF-8, или даже произвольные данные. Для примера предположим, что у нас есть база данных с текстом, закодированным в ISO-8859-2 (Latin-2), например, таблица словарных статей чешского и английского языков. Предположим, что у нас есть экземпляр, Connectionподключенный con к этой базе данных. Мы можем декодировать текст, закодированный в Latin-2, используя следующий код text_factory:

### 7.6. Маршрут регистрации

```python
@app.route('/register', methods=['GET', 'POST'])
def register():
    errors = []
    if request.method == 'POST':
        login    = request.form.get('login', '').strip()
        password = request.form.get('password', '')
        fullname = request.form.get('fullname', '').strip()
        phone    = request.form.get('phone', '').strip()
        email    = request.form.get('email', '').strip()

        if not re.fullmatch(r'[A-Za-z0-9]{6,}', login):
            errors.append('Логин: только латиница и цифры, минимум 6 символов')
        if len(password) < 8:
            errors.append('Пароль: минимум 8 символов')
        if not re.fullmatch(r'[А-Яа-яЁё\s]+', fullname):
            errors.append('ФИО: только кириллица и пробелы')
        if not re.fullmatch(r'8\(\d{3}\)\d{3}-\d{2}-\d{2}', phone):
            errors.append('Телефон: формат 8(XXX)XXX-XX-XX')
        if not re.fullmatch(r'[^@\s]+@[^@\s]+\.[^@\s]+', email):
            errors.append('Email: некорректный формат')

        if not errors:
            c = db()
            try:
                c.execute("INSERT INTO users(login,password,fullname,phone,email)"
                          " VALUES(?,?,?,?,?)",
                          (login, hash_pwd(password), fullname, phone, email))
                c.commit()
                c.close()
                return redirect('/login')
            except sqlite3.IntegrityError:
                errors.append('Логин уже занят')
                c.close()

    return render_template('register.html', errors=errors)

@app.route('/requests/create', methods=['GET', 'POST'])
def request_create():
    if 'user_id' not in session:
        return redirect('/login')

    errors = []
    c = db()

    if request.method == 'POST':
        room  = request.form.get('room', '').strip()
        date  = request.form.get('start_date', '').strip()
        pay   = request.form.get('payment', '').strip()

        if not room: errors.append('Введите название помещения')
        if not date: errors.append('Введите дату начала')
        if pay not in ('очное', 'СБП'): errors.append('Выберите способ оплаты')

        if not errors:
            r = c.execute("SELECT id FROM rooms WHERE name=?", (room,)).fetchone()
            if not r:
                errors.append('Помещение не найдено')
            else:
                s = c.execute("SELECT id FROM statuses WHERE name='Новая'").fetchone()
                c.execute("INSERT INTO requests(user_id,room_id,status_id,start_date,payment)"
                          " VALUES(?,?,?,?,?)",
                          (session['user_id'], r['id'], s['id'], date, pay))
                c.commit()
                c.close()
                return redirect('/requests')

    rooms = c.execute("SELECT name FROM rooms ORDER BY name").fetchall()
    c.close()

    return render_template('request_create.html', errors=errors,
                           rooms=[x['name'] for x in rooms])
```

@app.route('/requests/<int:rid>/review', methods=['POST'])
def add_review(rid):
    if 'user_id' not in session:
        return redirect('/login')

    text = request.form.get('text', '').strip()
    rat  = request.form.get('rating', '').strip()

    c = db()
    row = c.execute("""SELECT st.name AS s FROM requests r
                       JOIN statuses st ON st.id=r.status_id
                       WHERE r.id=? AND r.user_id=?""",
                    (rid, session['user_id'])).fetchone()

    if row and row['s'] == 'Завершено' and text and rat.isdigit() and 1 <= int(rat) <= 5:
        try:
            c.execute("INSERT INTO reviews(request_id,text,rating) VALUES(?,?,?)",
                      (rid, text, int(rat)))
        except sqlite3.IntegrityError:
            c.execute("UPDATE reviews SET text=?, rating=? WHERE request_id=?",
                      (text, int(rat), rid))
        c.commit()
    c.close()
    return redirect('/requests')

            var login    = document.getElementById('login').value.trim();
            var password = document.getElementById('password').value;
            var fullname = document.getElementById('fullname').value.trim();
            var phone    = document.getElementById('phone').value.trim();
            var email    = document.getElementById('email').value.trim();

            if (!/^[A-Za-z0-9]{6,}$/.test(login)) {
                errors.push('Логин: только латиница и цифры, минимум 6 символов');
            }

            if (password.length < 8) {
                errors.push('Пароль: минимум 8 символов');
            }

            if (!/^[А-Яа-яЁё\s]+$/.test(fullname)) {
                errors.push('ФИО: только кириллица и пробелы');
            }

            if (!/^8\(\d{3}\)\d{3}-\d{2}-\d{2}$/.test(phone)) {
                errors.push('Телефон: формат 8(XXX)XXX-XX-XX');
            }

            if (!/^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email)) {
                errors.push('Email: некорректный формат');
            }

            if (errors.length > 0) {
                e.preventDefault();
                showErrors(regForm, errors, 'reg-errors');
            }
        });
    }

    /* ============================================================
       ВАЛИДАЦИЯ ФОРМЫ ВХОДА
       ============================================================ */
    var loginForm = document.getElementById('login-form');

    if (loginForm) {
        loginForm.addEventListener('submit', function (e) {

            var errors = [];

            var login    = document.getElementById('login').value.trim();
            var password = document.getElementById('password').value;

            if (!login) {
                errors.push('Введите логин');
            }
            if (!password) {
                errors.push('Введите пароль');
            }

            if (errors.length > 0) {
                e.preventDefault();
                showErrors(loginForm, errors, 'login-errors');
            }
        });
    }

    /* ============================================================
       ФУНКЦИЯ ПОКАЗА ОШИБОК
       ============================================================ */
    function showErrors(form, errors, containerId) {

        var old = document.querySelector('[data-testid="' + containerId + '"]');
        if (old) {
            old.remove();
        }

        var div = document.createElement('div');
        div.className = 'errors';
        div.setAttribute('data-testid', containerId);

        div.innerHTML = '<ul>' + errors.map(function (err) {
            return '<li>' + err + '</li>';
        }).join('') + '</ul>';

        form.parentNode.insertBefore(div, form);
    }

});

### 12.4. Пример `api.py`

```python
from flask import Flask, request, jsonify
import sqlite3, os

app = Flask(__name__)
DB = os.path.join(os.path.dirname(__file__), 'shop.db')

STATUS_MAP = {
    'new':       'Новая',
    'paid':      'Оплачена',
    'shipped':   'Отправлена',
    'done':      'Выполнена',
    'cancelled': 'Отменена',
}


def db():
    c = sqlite3.connect(DB)
    c.row_factory = sqlite3.Row
    return c


def fmt_date(s):
    try:
        return f"{s[8:10]}.{s[5:7]}.{s[0:4]}"
    except Exception:
        return s


def fmt_address(u):
    parts = [u['city'], u['street'], f"д. {u['house']}"]
    if u['flat']:
        parts.append(f"кв. {u['flat']}")
    return ", ".join(parts)


def fmt_money(x):
    return f"{float(x):.2f}"


@app.route('/orders', methods=['GET'])
def orders():
    status = request.args.get('status')
    user_id = request.args.get('user_id')

    if status and status not in STATUS_MAP:
        return jsonify({'error': f'Недопустимое значение status: {status}'}), 400

    if user_id and not user_id.isdigit():
        return jsonify({'error': f'Недопустимое значение user_id: {user_id}'}), 400

    try:
        c = db()
        sql = """
            SELECT o.id, o.user_id, o.status, o.created_at,
                   u.last_name, u.first_name, u.middle_name,
                   u.city, u.street, u.house, u.flat
            FROM orders o
            JOIN users u ON u.id = o.user_id
            WHERE 1=1
        """
        params = []
        if status:
            sql += " AND o.status = ?"
            params.append(status)
        if user_id:
            sql += " AND o.user_id = ?"
            params.append(int(user_id))
        sql += " ORDER BY o.id ASC"

        rows = c.execute(sql, params).fetchall()

        result = []
        for o in rows:
            items = c.execute("""
                SELECT oi.quantity, p.title, p.price
                FROM order_items oi
                JOIN products p ON p.id = oi.product_id
                WHERE oi.order_id = ?
                ORDER BY oi.id ASC
            """, (o['id'],)).fetchall()

            item_list = []
            total = 0.0
            for it in items:
                s = float(it['price']) * int(it['quantity'])
                total += s
                item_list.append({
                    'title':    it['title'],
                    'quantity': int(it['quantity']),
                    'price':    fmt_money(it['price']),
                    'sum':      fmt_money(s),
                })

            result.append({
                'id':          o['id'],
                'buyer':       f"{o['last_name']} {o['first_name']} {o['middle_name'] or ''}".strip(),
                'status':      STATUS_MAP[o['status']],
                'created_at':  fmt_date(o['created_at']),
                'address':     fmt_address(o),
                'total':       fmt_money(total),
                'items_count': len(item_list),
                'items':       item_list,
            })

        c.close()
        return jsonify(result), 200

    except Exception as e:
        return jsonify({'error': str(e)}), 500


if __name__ == '__main__':
    app.run(host='127.0.0.1', port=8080, debug=True)
```

### 13.6. Возможные проблемы при запуске в РОСА Линукс

| Проблема | Причина | Решение |
|----------|---------|---------|
| `ModuleNotFoundError: No module named 'flask'` | Виртуальное окружение не активировано | Выполнить `source venv/bin/activate` |
| `Address already in use` | Порт 8080 занят другим процессом | Изменить порт в `app.run()` или завершить процесс: `sudo fuser -k 8080/tcp` |
| `Permission denied` | Нет прав на файл | `chmod +x app.py` |
| Браузер не открывает страницу | Сервер не запущен или порт заблокирован | Проверить статус: `curl http://127.0.0.1:8080` |
| `sqlite3.OperationalError: unable to open database file` | Нет прав на запись в папку | Проверить права: `ls -la`, при необходимости `chmod 755 project/` |
